# 归档：自动化分析流程 /pipeline（2026-10-11）

用户定案：15 阶段全自动流程（质控 → 宿主去除 → 定量识别 → 组装 → 注释 →
进化树/引物 → 报告串联）**不适合在本地电脑运行**，整页归档。分析改由顶部
各功能模块（/tools 分组卡）分步进行——每个模块卡本就有「✨ 示例」与
「👁 示例结果」入口，能力不缩水。

## 与 explorer 归档（2026-09-27）的区别：软归档

explorer 是自包含子系统，可整体移出；**pipeline 与样品基础设施深度耦合**，
只能做「页面归档 + 入口摘除 + 后端保留」：

| 处理 | 内容 | 原因 |
|---|---|---|
| 移入本目录 | `pipeline.html`（页面模板） | 唯一纯页面资产，路由已改重定向 |
| 摘除入口 | `_nav.html` 导航项、`home.html` 快捷卡、首页样品卡跳转（改 `/results`）、`download.html` 转样品跳转（改 `/samples`）+ 入队弹窗、`samples.html`「创建后加入队列」勾选框 | 无 UI 入口 = 功能不可达 |
| 保留 | `Virus_Platform_Core/pipeline.py`（run_analysis / STAGE_ORDER）、`/api/pipeline/create`（样品创建，samples/download 页共用）、`/api/pipeline/<name>`（样品状态，全局样品上下文 selectSample 每页都在用）、`/api/pipeline/<sample>/run`、`/api/queue/*`、`/api/analyze` | 样品登记/状态是全平台地基；引擎保留随时可恢复 |

安全性：批处理队列本就是「入队后**必须手动点启动**」设计（2026-09-20 定案，
见 `SampleQueue.add` 注释），启动按钮只存在于被归档的页面上 —— 归档后队列
自然休眠，不存在后台自动起跑 15 阶段的风险。

## 归档排查中顺带修掉的两个既有问题

排查"两个浏览器测试在 HEAD 上也红"时定位到两个与归档无关的存量缺陷：

1. **AI 事件流（SSE）连接泄漏**——`app-ai.js` 从不显式关闭 EventSource，
   服务端 `/api/ai/events` 生成器也没有断连检测（写心跳到半关连接永远
   "成功"）。每次导航泄漏 ~2 条 ESTABLISHED 连接 + 1 个服务端线程，攒到
   ~6 条（HTTP/1.1 同主机上限）后新 fetch 全部排队冻死——这正是
   `_it_global_ctx_ui.py` 第 [8] 段弹窗打不开、随后浏览器崩溃的根因，
   对真实用户连续切换模块时同样会发作。修复：
   - `app-ai.js` 在 `pagehide` 时 `AI._es.close()`（导航/刷新都会触发）；
   - `ai_assist.py` SSE 生成器加 300s 寿命上限（到期主动收尾，EventSource
     自动带 Last-Event-ID 重连续传，前端无感），并支持 Last-Event-ID 请求头
     （此前只认 `?since=` 查询参数，自动重连会整段回放环形缓冲）。

2. **一级导航在 1920 宽骑在换行临界点上**——14 个链接 + 上下文簇实测内容
   1674px vs 盒宽 1675px，字体度量随浏览器版本抖 1px 就把右侧胶囊簇挤到
   第二行（`_it_nav_responsive.py` 1920 断言红的根因）。修复：app.css 新增
   `max-width: 1980px` 档，链接内边距 11px→10px、间距 4px→3px，留出
   ~50px 余量。另外 640px 宽下两行物理放不下 14 项（内容 ~1285px > 两行
   上限 ~1224px），测试行数预算改为 ≤640px 允许 3 行（"被横条包住"仍由
   独立断言守住）。

## 恢复方法

从本目录拷回 `pipeline.html` 到 `webapp/templates/`，把
`Virus_Platform_Core/web/pages.py` 的 `/pipeline` 路由改回
`render_template('pipeline.html')`，在 `_nav.html` 导航清单加回
`('/pipeline', 'nav.pipeline', '自动化分析流程', '')` 即可——后端与
JS 逻辑（app-batch.js）从未移走。
