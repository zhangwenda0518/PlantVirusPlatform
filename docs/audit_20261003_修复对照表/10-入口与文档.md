## 未修复项 + 原因

1. **打包端到端验证（第 8 项）未跑全量**：`dev_tools/package.py` 默认即 GB 级产物、分钟-小时级耗时，本环境不适合整跑；改为"真实函数 + 真实收尾代码在临时产物目录上执行"的等价验证（已覆盖 git rev / 时间 / tools 原文 / 库统计 / --verify 两个分支）。全量打包仍建议在发布前由维护者执行一次 `python dev_tools/package.py --verify`。
2. **`3rd/` 下 122 项删除保留原样**：按清单要求"有意保留待用户决定"（3rd 是随包分发的第三方工具，是否随删除瘦身属发布口径决策，不在本子系统内擅动）。
3. **cmd.exe 读 UTF-8 多字节 .bat 的 EOF 误读（第 3 项残留现象）**：实测与内容无关的布局性怪癖（加/减一行即翻转），出现在所有真实命令执行完之后、不影响退出码与功能；修复前（HEAD GBK 控制台）该现象更严重（整段乱码 + rc=1）。为不引入 cargo-cult 式布局 hack 而保持现状，证据与复现方式已写入第 3 项。
4. **`dev_tools/build_virus_dbs.py` / `build_virus_db.py` 未加 ref_info 准入校验**：核实两者都不读带 `Category` 的 ref_info（分别读 `{source}_acc2taxid.tsv` 与 NCBI krakenuniq 源），在此加检查会是永远不触发的死代码；已改到真正消费 ref_info 的平台建库入口（第 20 项），并保留"只告警不阻断"语义。
