## 未修复项 + 原因

1. **第 33 项（`gb_collection.py:627-628`）**：修复前核实即已是目标形式（`gene_tag or (product.split()[0].lower() if product else 'gene')`，条件表达式已带括号），若再改会变成无意义改写 → **未改**。已用真实 GenBank 记录验证行为正确（`/product` 首词入 tag，不塌进 `gene` 桶）。
2. **`standardize_metadata_df` 的 null 清空分支在 pandas 3.x 下不执行**（邻近发现，非清单内）：该函数用 `if df[col].dtype == object` 作门控，而本机/内置 pandas 3.0.3/3.0.5 中字符串列 dtype 为 `str`，故「'missing'/'not collected' → NA」的规则清空与本次加的 `rule` provenance 钩子在该环境下不会触发（pandas 2.x 或 object 列才会）。第 28 项只要求 provenance 改造，改 dtype 判断会**改变数据输出**，超出本次范围 → **未改**；provenance 钩子已就位（object dtype 路径实测通过）。建议单独立项把判断改为 `pandas.api.types.is_string_dtype` 兼容。
3. **`main.py:487`（`cmd_host_genome`）仍以 in-process `sys.argv` 传 `--ncbi-api`**：非子进程调用，密钥只存在于本进程内存的 argv，不出现在 OS 进程表/任务日志，且 `host_genome` 未列入第 32 项清单 → **未改**（若要彻底统一，需给 `host_genome.main()` 加 env 读取）。
4. **`_server_collect.py` manifest 对 >500MB 文件跳过 sha256**：按清单要求（"大文件>500MB 跳过并标注"）实现，跳过项以 `note: skipped_size>500MB` 标注，属预期行为而非缺项。
