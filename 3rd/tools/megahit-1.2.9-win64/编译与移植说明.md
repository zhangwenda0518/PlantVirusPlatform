# MEGAHIT v1.2.9 Windows 编译与移植说明

记录在 Windows 11 上从源码原生编译 MEGAHIT v1.2.9 的完整过程、全部源码改动及其原因，便于复现与后续升级。

## 1. 编译环境

| 组件 | 版本 / 路径 |
| --- | --- |
| 系统 | Windows 11 Pro for Workstations 26200 (x64) |
| 编译器 | MinGW-w64 gcc/g++ **16.2.0**，UCRT 运行时，posix 线程模型，seh 异常 |
| 构建系统 | CMake 4.4.3 + Ninja 1.13.2 |
| zlib | 1.3.2（MinGW 自带静态库 `libz.a`） |
| Python | 3.12.10 embeddable（仅运行驱动脚本） |

> 未使用 MSVC、MSYS2、conda、WSL。构建目录放在纯 ASCII 路径下（`D:\megahit-win`），因为 MinGW 工具链对非 ASCII 路径支持不稳。

获取源码：

```bat
git clone --depth 1 --branch v1.2.9 https://github.com/voutcn/megahit.git
```

配置与编译（`<mingw>` 指 MinGW 安装前缀）：

```bat
cmake -S src -B build -G Ninja ^
  -DCMAKE_BUILD_TYPE=Release ^
  -DCMAKE_C_COMPILER=<mingw>/bin/gcc.exe ^
  -DCMAKE_CXX_COMPILER=<mingw>/bin/g++.exe ^
  -DZLIB_INCLUDE_DIR=<mingw>/x86_64-w64-mingw32/include ^
  -DZLIB_LIBRARY=<mingw>/x86_64-w64-mingw32/lib/libz.a ^
  -DCMAKE_EXE_LINKER_FLAGS="-static"

cmake --build build
```

## 2. 源码改动（共 6 处，均不涉及组装算法）

### 2.1 新增 `src/win-compat/sys/resource.h`

MinGW 没有 `<sys/resource.h>`，而 `src/utils/utils.h` 直接包含了它，且
`AutoMaxRssRecorder::watch()` 调用 `getrusage()` 记录峰值内存。
该兼容头提供 `struct rusage`、`RUSAGE_SELF` 和内联 `getrusage()`，
用 Win32 `GetProcessTimes` + `K32GetProcessMemoryInfo` 实现。

### 2.2 `CMakeLists.txt`

| 改动 | 原因 |
| --- | --- |
| `if (WIN32) include_directories("${CMAKE_SOURCE_DIR}/win-compat")` | 让上面的兼容头生效 |
| `cp` → `${CMAKE_COMMAND} -E copy` | Windows 无 `cp` |
| `megahit_toolkit` 由 `create_symlink` 改为复制 `megahit_core_no_hw_accel.exe` | Windows 普通用户无符号链接权限 |
| WIN32 追加 `-mno-ms-bitfields` | **关键**：MinGW 默认沿用 MSVC 位域布局，使 `sizeof(UnitigGraphVertex)` 变成 56，触发 `src/assembly/unitig_graph_vertex.h:152` 的 `static_assert(sizeof(UnitigGraphVertex) <= 40)`；加上该选项后恰为 40，与 Linux 一致 |
| `-D__XROOT__='...'` 仅在非 WIN32 定义 | 单引号在 Windows 上会变成多字符字面量，报 `invalid conversion from 'int' to 'const char*'`；`utils.h` 会退回用 `__FILE__` 取文件名 |
| WIN32 追加 `-Wl,--stack,268435456` | Windows 默认线程栈仅 1 MB，`megahit_core count` 会栈溢出（`0xC00000FD`）；已用 `SizeOfStackReserve` 确认生效 |

### 2.3 `src/megahit`（Python 驱动脚本）

| 改动 | 原因 |
| --- | --- |
| 新增 `_IS_WINDOWS` / `_EXE_SUFFIX`，`SoftwareInfo` 中的 `megahit_core*` 加 `.exe` | Windows 可执行文件带后缀 |
| 新增 `cpu_affinity_count()` | `os.sched_getaffinity` 在 Windows 不存在 |
| `detect_available_mem()` 增加 Windows 分支（ctypes `GlobalMemoryStatusEx`） | 原实现只认 `/proc/meminfo` |
| `inpipe_cmd()` 在 Windows 返回空串 | 无 `mkfifo`，也不假定系统有 gzip/bzip2 命令 |
| 新增 `resolve_input()` | Windows 上只用标准库 `bz2` 解压 `.bz2` 到 `tmp\`；`.gz` 与纯文本直接交给核心程序（核心用 kseq+zlib 原生支持 gz） |
| `merge_final()` 增加 Windows 分支 | 原实现用 `cat ... \| filterbylen` 管道，改为 Python 拼接 + `Popen` 调用 `megahit_core filterbylen` |
| `close_logger()` / `add_console_logger()` 增加空值保护 | 未指定 `--log-file` 时原代码抛 `AttributeError` |
| `create_library_file()` 改为**制表符分隔**文件名 | 见 2.6 |
| 内置 Python 的 `python312._pth` 取消注释 `import site` | 否则 `exit(0)` 报 `NameError: name 'exit' is not defined` |

### 2.4 `src/sequence/io/binary_reader.h`

打开文件时显式使用 `std::ifstream::binary`。
Windows 文本模式会把 `\r\n` 折叠，破坏 `.bin`/`.cand` 等二进制记录，
症状是 `malloc(): corrupted top size` 并以 `0xC0000409` 崩溃。

### 2.5 `src/sdbg/sdbg_raw_content.cpp`

`.sdbg.N` 在 POSIX 下用 mmap 读写；Windows 上必须以二进制模式打开，
否则文本模式转换会破坏 `SdbgMeta` 头部。

### 2.6 `src/sequence/io/sequence_lib.cpp`

`SequenceLibCollection::Build()` 原来用 `istream >>` 依次读类型和文件名，
而 `>>` 以空格分隔——路径中含空格时（如 `D:\my data\r1.fa`）会被截断成
`D:\my`，随后因文件打不开而崩溃。
改为：整行读取后按 `\t` 切分（首字段为类型，其余为文件名），
对旧式空格分隔的行仍保留回退解析。

## 4. 已知限制

1. 核心程序使用窄字符 `fopen`，路径编码依赖系统 ANSI 代码页；中文 Windows 下正常，但跨语言环境（如 UTF-8 beta 选项）可能出现乱码，**建议输入输出用英文路径**。
2. 不支持 `--continue` 之外的中断恢复以外的并行调度特性（与上游一致）。
3. 未启用 `-march=native`，以保证在任何 x86-64 CPU 上都能运行（运行时由驱动脚本自动挑选 POPCNT/BMI2 版本）。
4. 与上游一致，`megahit_core` 需要 Windows 10/11 自带的 UCRT（`api-ms-win-crt-*.dll`）；Windows 7/8 需另装 VC++ 2015-2022 运行库。

## 5. 复现脚本要点

1. 装好 MinGW-w64（UCRT 版）、CMake、Ninja。
2. 按第 1 节配置编译。
3. `strip --strip-all` 可把每个 exe 从约 6.2 MB 降到约 4.0 MB（已验证不影响运行）。
4. 组装便携包：`bin\` 放四个 exe 与 `megahit.py`；`share\megahit\test_data\` 放官方测试数据；根目录放 `megahit.bat`。内置 Python 的独立包另外把 Python embeddable 解压到 `python\`，图形界面版再加 `megahit_gui.py`、`启动MEGAHIT图形界面.bat`、`pytk\`。
