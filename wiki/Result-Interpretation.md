# 结果解读规则（Result Interpretation）

> 平台结果 → 生物学结论的**数字化判据表**。所有阈值来自平台代码常量
> （标注出处），解读规则借鉴 MMPV-RNA 平台的结果分析体系
> （`docs/MMPV-RNA结果解析与绘图学习笔记.md` §3）。
> 纪律：**只给数据支持的结论**；缺产物写 `N/A（阶段未运行）`，绝不推断；
> 与本文阈值冲突时在结论中显式标注，而不是改叙事。

---

## 1. 候选序列验证（③b verify）

代码出处：`Virus_Platform_Core/verify.py:33-54`

| 判据 | 阈值 | 结论 |
|---|---|---|
| 序列长度 ≥ 1000 nt | `LEN_VIRUS_MIN` | 走病毒分支 |
| 序列长度 ∈ [200, 1000) | `LEN_VIROID_MIN` | 走类病毒分支；<200 不处理 |
| 已知病毒 | blastx identity ≥ **85%** 且覆盖 ≥ **85%**（`VIRUS_KNOWN_IDENT/COV`） | known |
| 新病毒候选 | identity ≥ **40%** 且覆盖 ≥ **50%**（`VIRUS_NOVEL_IDENT/COV`） | novel（有病毒蛋白证据但非已知种） |
| 类病毒 | identity ≥ **80%** 且覆盖 ≥ **60%**（250–300 bp 放宽到 40%，`VIROID_MIN_*`） | viroid |

**解读**：novel ≠ 新种，只是"不能归入已知种"——需结合 ORF 注释（⑥b）的
科/属归属与 SDT 相似度（⑦）进一步定性。identity 在 40% 以下、仅有结构域
证据的 contig 归"未分类"，入组需谨慎。

## 2. 已知病毒定量过滤（②b kvsuite）

代码出处：`known_virus_suite/known_virus_suite.py:194-197`（CLI 默认值）

高置信判定 = 同时满足：覆盖率 ≥ **10%**、平均深度 ≥ **0.5×**、reads ≥ **10**、
TPM ≥ **1.0**。任一不满足进 discarded（报告里有完整留痕）。

**解读**：
- "检出"与"高置信"是两个口径——`identify/all_viruses.summary.tsv` 是宽召回层，
  `filter/filtered.tsv` 才是结论层；论文引用数字一律用过滤后口径。
- TPM 用于跨样本比较丰度；reads 数用于绝对存在性。只报 TPM 不报 reads
  会被审稿人质疑低丰度样本的可信度。

## 3. 共识序列与变异（③c consensus）

代码出处：`Virus_Platform_Core/consensus.py:55-74`

| 判据 | 阈值 | 含义 |
|---|---|---|
| 位点计入共识 | 深度 ≥ **4×**（`MIN_DEPTH`）且碱基质量 ≥ **20**、MAPQ ≥ **10** | 低于此深度的位点共识不可信 |
| 共识碱基 | 等位频率 ≥ **0.5**（`MIN_FREQ`） | 主流碱基 |
| iSNV（种内单核苷酸变异） | 次等位频率 ≥ **2%** 且支撑 reads ≥ **2** 条（`MIN_MINOR_FREQ/COUNT`） | 准种/混合感染信号 |
| 病毒"真实存在"判定 | 覆盖度 ≥ **10%**（`MIN_COV_PCT`） | summary 里的 present/low_support 分级 |

**解读**：
- iSNV 频率 2%–50% → 准种位点；接近 50% 可能是两个基因型的混合感染，
  要回到覆盖度曲线看是否有双峰。
- `low_support`（覆盖不足 10%）的参考基因组不作为"该病毒存在"的证据，
  只写"检测到部分匹配"。

## 4. SDT / identity 相似度（⑦ phylo 与 sdt 工具）

通用病毒学口径（平台 SDT 热图与 identity 矩阵的解读基准）：

| 全基因组/片段 nt identity | 结论 |
|---|---|
| ≥ **95%** | 同一株系（same strain） |
| **85%–95%** | 同种不同分离物（种内） |
| < **85%** | 不同种（种间）；< **40%** 通常已出科/属 |

**解读**：identity 需与覆盖度一起看——短片段高 identity 不能下"同株"结论；
 pairing 覆盖 < 50% 时 SDT 值只代表局部相似。

## 5. 重组分析（rdp 工具，RDP5 引擎）

**高置信重组事件判据：≥ 3/7 种方法（RDP/GENECONV/BootScan/MaxChi/
Chimaera/SiScan/3Seq）支持**（MMPV 口径，平台 `rdp5.csv` 的 Methods 列
记录每种事件的方法数）。<3 种方法视为候选，需 DnaSP Rm 或断点分布交叉验证。

**断点分布退化守卫**（平台已有，`rdp5_engine.py:367`）：RDP5 自带断点分布
CSV 静默全 0 时，平台按事件断点自动重建 200 nt 滑窗分布——读到"重建"
标记时注明"分布由平台合成，非 RDP5 原生输出"。

**解读**：断点落在保守区内（如聚合酶核心）比落在间隔区更值得跟进；
重组事件间的断点位置聚集（多事件同一窗口）提示重组热点而非随机事件。

## 6. 时间信号与定年（rtt / phylodyn）

代码出处：`rtt_drt.py:315-335`（平台已弃用单一固定阈值）

| 判据 | 口径 | 结论 |
|---|---|---|
| 旧判据 | root-to-tip 最大 R² ≥ **0.5** | 仅作参考对比保留 |
| **管道口径（采用）** | DRT 置换检验：真实 R² ≥ 随机化分布 **95 百分位**（`passed_percentile95`） | 有时间信号，可进入 BEAST/Treetime 定年 |
| 经验口径 | 置换 p ≤ **0.05** | 同上 |

**解读**：DRT 未通过时**不报分化时间/TMRCA**，写"未检测到足够时间信号
（可能因样本时间跨度不足或重组干扰）"——定年前置门，不是事后过滤。
RTT R² > 0.9 时注意检查是否由群体结构（按地点聚类）驱动而非时间驱动。

## 7. 审计交付模板（RESULTS / AUDIT 双交付）

按 MMPV 结果分析技能的骨架，对任何一次分析输出两份 Markdown：

**`RESULTS_*.md`（叙事）**：每个关键数字后括注来源文件，如
"检出病毒 15 种（`02b_kvsuite/summary.json: species_detected`）"。

**`AUDIT_*.md`（质检表）**：固定审计项，逐项 PASS/WARN/FAIL：

| 审计项 | 判据 |
|---|---|
| 漏斗单调性 | 每层记录数 ≤ 上一层（报告"流程漏斗"章节），违反即 FAIL |
| 过滤通过率 sanity | 高置信层/宽召回层比例异常高 → 过滤未咬合；异常低 → 阈值过严 |
| 分母一致性 | 检出率类指标的分母必须是"通过预筛的样本数"，不是全部样本 |
| 缺产物登记 | 缺阶段一律写 `N/A（阶段未运行）`，不得写 0 |
| 数字可回溯 | 每个结论数字能指到 `07_report/fig_manifest.json` 登记的源文件 |

## 附：写作避坑（平台实测教训）

1. **reads 对 vs reads 条**：宿主去除统计按"对"（pairs），kvsuite 定量按
   "条"（reads/fragments，随引擎变化）——两个数字不可直接相除，报告 KPI
   卡与漏斗图已标注口径。
2. **iVar/bcf 类 sites-only VCF 无基因型列**：变异可视化必须走
   AF/allele_frequencies 路径（平台已处理），不要用 GT 重建基因型矩阵。
3. **dS≈0 的基因对比值爆炸**：dN/dS 只对 dS>0 子集计算并记录被剔对数。
4. **%g 格式化科学计数**（1e+02%）绝不允许出现在图上——留存率等百分比
   用定点格式（已在 `stage_funnel.plot_retention` 落实）。
